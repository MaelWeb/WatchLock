## 2. 设计原则

1. **状态优先**：菜单栏第一屏只回答一个问题——「现在安全吗」。
2. **渐进披露**：菜单栏只留 3 个主操作，其余全部收进设置窗口。
3. **一处一容器**：任何窗口内不出现嵌套滚动；内容超一屏靠信息架构拆分，不靠塞滚动区。
4. **系统一致性**：遵循 macOS HIG，用 SwiftUI 原生语义（不自定义控件皮肤、不发明新的控件形态）。

## 3. 设计语言（Design Tokens）

落地为 `Sources/WatchLock/UI/Design/WLTheme.swift`，全部为静态常量 + ViewModifier，禁止界面里再写裸数字。

**间距**（4pt 网格）
```
xxs 2 · xs 4 · sm 8 · md 12 · lg 16 · xl 24 · xxl 32
卡片内边距 lg(16)；卡片间距 md(12)；标签与数值间距 sm(8)
```

**圆角**
```
sm 6（chip/进度条） · md 10（卡片/按钮） · lg 14（大卡片）
```

**语义色**（用 `Color(NSColor.*)` 动态色 + `@Environment(\.colorScheme)`，不硬编码 `.green/.orange`）
| token | 含义 | 用于 |
| --- | --- | --- |
| `wlSuccess` | 安全 / 成功 | near 状态、绑定成功 |
| `wlWarning` | 边界 / 注意 | far 状态、模拟信号中、无有效 RSSI |
| `wlDanger` | 错误 / 破坏性 | 扫描错误、解除绑定、清空日志 |
| `wlNeutral` | 未定 / 停用 | unknown / paused / disabled、次要文本 |
| `wlAccent` | 强调 | 主按钮、选中态（跟随系统强调色） |

**字体层级**
```
状态标题   WLFont.statusTitle = .title3 + semibold  (15)
正文       WLFont.body        = .body               (13)
次要说明   WLFont.caption     = .subheadline        (11) + .secondary
数值       WLFont.caption / WLFont.body + .monospacedDigit
日志/抓包  .caption.monospaced()
```
> macOS 的文本样式字号与 iOS 不同：`.headline` 是 13、`.caption` 是 10，直接用会比上面的层级整体偏小，
> 所以统一走 `WLFont`，不要在视图里再写 `.headline` / `.caption` 来凑设计稿字号。

**信号分级**（`SignalMeter`，4 格）— 关键设计点：**按当前阈值动态映射**，保证「看到的格子数」和「会不会锁屏」永远一致。
```
RSSI ≥ nearRSSI            → 4 格  wlSuccess
nearRSSI .. (near+far)/2   → 3 格  wlSuccess
(near+far)/2 .. farRSSI    → 2 格  wlWarning
RSSI ≤ farRSSI             → 1 格  wlWarning
无信号 / RSSI ≥ 0          → 0 格  wlNeutral
```

## 4. 信息架构重构

设置窗口：`TabView(5 tab)` → **侧栏 `NavigationSplitView`**，并把「高级」拆开。

```
通用 / 设备 / 解锁 / 校准 / 诊断 / ── / 关于
```
- **校准**：校准向导 + 距离模型（原高级前半）
- **诊断**：误锁调参 + 诊断日志 + 广播抓包 + 调试开关（原高级后半）

理由：每页内容控制在一屏内，从根上消除 B2 的嵌套滚动。

窗口尺寸：`TabView` 的固定 `frame(560×460)` → `.frame(minWidth: 660, minHeight: 480)`，允许系统记忆用户调整后的尺寸。

### 5.1 菜单栏面板（宽 340）

```
┌──────────────────────────────────────────────┐
│ 🔓  手表在身边                      ●━━━━    │  标题行：状态图标 + 标题 / 设备名；右侧主开关
│     Apple Watch                    自动锁定  │  开关下一行小字
│ ⚠ 蓝牙扫描中断，正在重试          ← 异常时插入 │  告警：直接贴在标题行下，不入卡
│                                              │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐       │  MetricTile ×3：大数字 + 小单位
│ │ 信号 ▂▄▆█ │ │ 距离      │ │ 更新      │       │
│ │ -48 dBm  │ │ 0.6 米   │ │ 12 秒前  │       │
│ └──────────┘ └──────────┘ └──────────┘       │
│ 上次锁定                 14:05 · 超出距离     │  仅有记录时出现
│                                              │
│ ┌────────────┬────────────┬────────────────┐ │
│ │  立即锁定   │    暂停     │   设置…        │ │  3 个主操作（等宽）
│ └────────────┴────────────┴────────────────┘ │
│ ──────────────────────────────────────────── │
│  更多 ⌄                     模拟：-85 dBm    │  次要入口
└──────────────────────────────────────────────┘
  暂停态 / 误锁反馈行：触发时插在三块瓦片与主操作之间
```

要点
- **不再套状态卡**（设计稿 `.scratch/menubar__d-metric-tiles`）：层级靠留白，不靠底色。标题行 = `StatusIcon`（20pt，语义色，与菜单栏同源的 `MenuBarIcon`；「已关闭」态图标自带 42% 淡化，故用主色承载避免过淡）+ 状态标题 + 设备名；主开关并入标题行右侧，下方一行 11pt 小字「自动锁定」，省一张卡。
- **三块指标瓦片** `MetricTile`：信号 / 距离 / 更新。数字 17 semibold + 等宽数字，单位 11pt 次要色；信号瓦片右上角放 `SignalMeter`（4 格，**按当前阈值分级**，与判定引擎同口径）。读数换算在 `MenuBarMetrics`（纯函数，有单测）：RSSI ≥ 0（含 macOS 的 127）→ 「—」；距离 ≤ 0 → 「—」；更新时间 < 60 秒按秒、之后按整分钟向下取整。
- 「最后更新」从副标题挪到「更新」瓦片；副标题只剩设备名。距离是由 RSSI 估算的，瓦片里只显示一位小数，不加「约」（取舍：估算误差不在界面上表达）。
- 告警按优先级只显示一条（扫描器问题 > 会议 / 演示暂缓锁定 > 未绑定手表），直接放在标题行下。
- **取舍**：开关的标签缩成 11pt 小字；开关本身仍保留 VoiceOver 标签「启用自动锁定」，小字对辅助功能隐藏。
- 曾有的 `ProximityGauge` 距离刻度与 `StatusCard` / `CardSection` 已随本方案删除；`ProximityZone` 分区逻辑保留（设置页 `ThresholdBand` 图例使用），`SignalMeter` 仍用于设备列表（`DeviceTile`）。
- 主操作收敛为 3 个：`立即锁定` / `暂停…` / `设置…`。`暂停…` 为 Menu（15 分钟 / 1 小时 / 4 小时）。
- 暂停态用**整行状态条**，显示剩余时间 + 「恢复」。
- 误锁反馈：仅在 `falseLockFeedbackAvailable` 时出现，作为上下文行（不占位时不渲染）。
- 调试菜单收进「更多 ⌄」，仅**开发者模式**（`DeveloperMode`）下显示；退出按钮一并收进去，降低误触。
- `立即锁定` 保持一键（效率优先），但**不使用 prominent 样式**，并在「通用」新增可选开关「立即锁定前确认」（默认关）。*【待确认：是否需要默认开启确认】*

#### 5.1.1 系统玻璃材质（Liquid Glass）适配

面板背景**不自绘**，交给系统：`MenuBarExtra(.window)` 的面板在 macOS 26 上自动采用 Liquid Glass，前提是 App 用**最新 SDK** 构建。依据均来自 Apple 官方文档（2026-10-20 读取 Markdown 版）：

| 依据 | 对本面板的约束 |
| --- | --- |
| 《Adopting Liquid Glass》："standard components like bars, sheets, popovers, and controls automatically adopt this material"；需"build with the latest SDKs" | 发布产物必须链接 macOS 26 SDK；CI 用 `macos-26`，并由 `Scripts/verify-liquid-glass-sdk.sh` 在构建后校验 |
| 同上："Audit the backgrounds of sheets and popovers … remove those custom background views" | 面板根视图**不加** `.background` / 视觉效果视图（现状已满足）；不要手动包 `NSVisualEffectView` |
| 同上："Avoid overusing Liquid Glass effects … avoid overcrowding or layering" | 面板内按钮保持标准 `.bordered`，**不改** `.glass` / `glassEffect`；不在玻璃上再叠玻璃 |
| HIG《Materials》："Don't use Liquid Glass in the content layer … use standard materials" | 卡片（内容层）继续用 `.quaternary` 这类标准填充，不用 `glassEffect` |
| HIG《Materials》：regular 变体"when components have a significant amount of text, such as alerts, sidebars, or popovers" | 面板文字多，应保持系统默认的 regular 玻璃；不选 clear（clear 仅用于媒体等视觉丰富背景） |
| 同上："Test your app's custom elements, colors … with different configurations" 与"increased contrast option" | 面板内不再有自绘半透明层（`ProximityGauge` 已删除）；瓦片用 `.quaternary` 标准填充，由系统处理对比度 |
| 《UIDesignRequiresCompatibility》：设为 YES 会"display the app as it looks when built against previous versions of the SDKs"，且"temporarily" | **不设置**该键（等于放弃玻璃）；发布测试会拦截 |

**范围与限制（务必区分）**
- **文档已证实**：新 SDK 构建 → 标准 popover 自动用新材质；不要自加背景；内容层不用 Liquid Glass。
- **本次实测**：线上 `/Applications/WatchLock.app`（1.0.0）链接 **SDK 15.5**；本地构建链接 SDK 26.2。用 `otool -l` 读 `LC_BUILD_VERSION` 得到，非推测。
- **文档未回答**：旧 SDK 链接的 App 在 macOS 26 上默认是否保持旧外观（`UIDesignRequiresCompatibility` 页面明确"原文未提及"）。因此**不能**断言"1.0.0 的毛玻璃问题就是由旧 SDK 造成"，只能说"升到新 SDK 是 Apple 规定的适配路径"。
- **待真机验证**：升级后面板顶部 / 底部色带是否消失；瓦片（`.quaternary`）在 Liquid Glass 面板上的实际观感；macOS 14 / 15 上外观是否不变（`LSMinimumSystemVersion` 保持 14.0）。
- **不在本节范围**：设置窗口 / 引导窗口（自建 `NSWindow`）的玻璃适配另议。

### 5.2 设置窗口 · 通用

```
┌────────┬───────────────────────────────────────────────────┐
│ 通用    │  启用自动锁定                            ●━━━━━━━ │
│ 设备    │                                                   │
│ 解锁    │  距离阈值                                          │
│ 校准    │  ┌─────────────────────────────────────────────┐  │
│ 诊断    │  │  ━━━━━━●━━━━━━━●━━━━━━━┃━━━                  │  │  已离开 / 在身边 把手 + 当前信号竖线
│ ──────  │  │  ┃ 当前 -48 dBm · 在身边          间隔 15 dBm │  │
│ 关于    │  ├─────────────────────────────────────────────┤  │
│        │  │  ● 在身边                      -55 dBm   ▲▼  │  │  行首圆点与把手同色
│        │  │  ● 已离开                      -70 dBm   ▲▼  │  │
│        │  │    离开后等待                      5 秒   ▲▼  │  │  数值右置、等宽数字
│        │  │    信号丢失视为离开               20 秒   ▲▼  │  │
│        │  │    收不到信号时按「已离开」锁定      ●━━━━━━━   │  │
│        │  └─────────────────────────────────────────────┘  │
│        │  阈值越接近越容易误锁，已强制保留 5 dBm 间隔。…       │
│        │                                                   │
│        │  锁定方式 / 自动锁定的例外 / 其他（同上，Form 分组）   │
└────────┴───────────────────────────────────────────────────┘
```

要点（解决 B4）
- 两个独立 Slider → **同轴阈值带 `ThresholdBand`**：一根刻度条 + 3 个把手（`已离开` / `在身边` 可拖，`当前信号` 只读）。
- 拖动时自动 clamp，强制 `near − far ≥ 5 dBm`；非法组合不可能被设出。
- 该 clamp 逻辑抽成纯函数，补单元测试（见 §7）。

**2026-10-20 更新 · 数值行分列**（`ValueStepperRow`，探索与取舍见 `.scratch/INDEX.md`「settings__a」）
- 数值项改为「标签 … 数值 + 步进器」：数值右置、等宽数字，步进器隐藏文字标签但保留 VoiceOver 标签与值。原先把数字嵌进标签句子（「离开后等待 5 秒再锁定」），多行并排时数字上下不对齐。
- 「在身边 / 已离开」行首加 7pt 圆点，与阈值带把手同色；图例因此不再重复写两个阈值的数值，只保留「当前信号 · 所在分区」与间隔。当前信号无效（含 macOS 回传的 127）时写「当前：无信号」，不编造数值。
- 单位文案集中在 `ValueFormat`（`dBm` / 秒 / 分钟），有单测。

## 7. 交互与无障碍

- **破坏性操作二次确认**：解除绑定、清空日志、清除钥匙串密码（`wlDanger` + `.confirmationDialog`）。
- **无障碍**：所有按钮补 `.help()`；图标补 `accessibilityLabel` / 装饰图 `accessibilityHidden`；`SignalMeter` 暴露 `accessibilityValue`（如「信号 4 格中的 3 格」）。
- **动态字体**：移除包裹文本的固定 `frame(height:)`；日志区改为该页独占高度的 `List`。
- **深色模式 / 增强对比**：语义色走动态色，不写死 `.green` / `.orange`。
- **键盘**：菜单栏 `⌘,` 打开设置保持；`Esc` 关闭 popover；设置窗口标准 `Tab` 导航与焦点环。
- **最小点击区**：所有可点元素 ≥ 24×24pt。
- **纯函数单测**（新增，放 `Tests/WatchLockTests/`）：
  - `ThresholdBand` 的 clamp（`near − far ≥ 5`、越界裁剪）
  - `SignalMeter` 的分级映射（含无信号 / RSSI=127 的 macOS 已知异常值）
  - 空态文案选择逻辑（蓝牙状态 × 扫描状态 × 广播数）

## 10. 已知限制（实施后）

- SwiftUI 菜单栏 popover 的视觉细节（圆角、阴影、间距）无法在 CI 中校验，只能靠 `swift build` + `swift test` 保证编译与逻辑正确；真机观感需你实际打开确认。
- 部分 macOS 14 SwiftUI API（如 `ContentUnavailableView`、`SettingsLink`）在 SPM 无 asset catalog 打包下行为一致，但图标资源需确认 bundle 内可用。
